# Compass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a compass that shows north, turns the map in 22.5° steps and resets to north out of 3D. Make a tilt by hand turn 3D on, and tilting back flat turn it off.

**Architecture:**
- `js/map.js` gains camera functions and two subscriptions, one to camera moves and one to the reader's tilts.
- A new `js/compass.js` draws the control once for both layouts, and `style.css` shapes it per layout.
- `js/app.js` connects the two and routes every way of switching 3D through one function. That function keeps the 3D button, the address, the notice and the compass consistent.

**Tech Stack:** Plain ES modules, MapLibre GL JS. Tests use `node --test`, jsdom and the strict fake map in `tests/helpers/browser.js`.

**Spec:** `docs/superpowers/specs/2026-11-01-compass-design.md`

## Global Constraints

- `AGENTS.md` holds:
  - build DOM with `h()` or nodes, never HTML interpolation;
  - no `style` attributes, so set the needle's transform through `node.style`;
  - keep every asset path relative;
  - add every new `js/` module to the `modulepreload` list in `index.html`.
- Compass: 54 × 40 px, round ends of radius 20. Three buttons 15, 24 and 15 px wide, each 40 px tall. The arrows draw over them and don't catch the pointer.
- Arrow and needle geometry, copied from the spec (capsule coordinates 54 × 40, needle 28 × 28):
  - left arc `M13.25 8.89 A13 13 0 0 0 9.1 27.08`, left head `6.08 29.04 12.37 32.11 12.12 25.12`;
  - right arc `M40.75 8.89 A13 13 0 0 1 44.9 27.08`, right head `47.92 29.04 41.63 32.11 41.88 25.12`;
  - needle north `14,0 18.7,14 9.3,14`, needle south `9.3,14 18.7,14 14,28`.
- Colors:
  - arrows `#202124` (`var(--text)`), 2 px stroke, round cap, filled head;
  - needle north `#d93025` (`var(--red)`), south `#bdc1c6`;
  - hover `#f1f3f4`.
- Labels: group "Map direction"; buttons "Rotate left", "Rotate right" and "Face north", each with a matching `title`.
- Rotate step: 22.5°. Rotate left adds to the bearing, so the map turns counter-clockwise.
- Tilt threshold: 5°.
- North-facing: `Math.abs(bearing) < 0.5`. MapLibre's 7° `bearingSnap` stays at its default.
- Desktop column: centred. The 3D and zoom buttons become 36 × 36 with 11 px corners. The compass sits first.
- Phone compass:
  - round, 44 px, needle only;
  - in the column under the 3D button;
  - shown while the map isn't north-facing or 3D is on;
  - eases in and out with opacity and scale over 160 ms, with no transition under `prefers-reduced-motion`.

## Review Focus

1. The page's own camera moves never switch 3D: the 3D button's 60° ease, `setTerrain(false)`, the compass reset, and `?3d=1` on load. Only an event that carries `originalEvent` counts. Tested in Task 3. The `?3d=1` load is already covered by `tests/app-glacier-view.test.js`, which must keep passing.
2. A bearing with float noise, such as `1e-9` or `-0`, counts as north, so the phone compass hides. Tested in Task 2.
3. Tilting flat by hand while turned leaves 3D, keeps the bearing, and keeps the phone compass visible. Tested in Task 3.
4. Tilting into 3D by hand writes `?3d=1`, presses the button and shows the terrain notice the first time, without the 60° ease. Tested in Task 3.
5. Leaving 3D through the compass leaves the same state as the 3D button: unpressed, notice hidden, `?3d` gone and terrain off. Tested in Task 3.

### Task 1: Camera functions on the map and gesture events on the fake

**Files:**
- Modify: `js/map.js` (`setTerrain` in the `api` object at about line 512; new members beside `onMove`)
- Modify: `tests/helpers/browser.js` (`FakeMap.easeTo`, new `FakeMap.gesture`)

**Interfaces:**
- Produces, on the object `createMap` resolves with:
  - `setTerrain(on: boolean, { move = true }: { move?: boolean } = {}): void`. With `move: false` it only adds or removes the terrain and leaves the camera alone. The default keeps today's eases: `{ pitch: 60 }` on, and `{ pitch: 0, bearing: 0 }` off.
  - `rotateBy(degrees: number): void`. Calls `map.easeTo({ bearing: map.getBearing() + degrees })`.
  - `faceNorth(): void`. Calls `map.easeTo({ bearing: 0, pitch: 0 })`.
  - `level(): void`. Calls `map.easeTo({ pitch: 0 })`.
  - `onCamera(callback: ({ bearing: number, pitch: number }) => void): void`. Called on every MapLibre `move` event.
  - `onTilt(callback: (pitch: number) => void): void`. Called on `pitchend` only when the event has `originalEvent`, with `map.getPitch()`.
- Produces, on `FakeMap`:
  - `easeTo(options, eventData = {})`. After setting the camera it fires `move` with `eventData`, then `pitchend` if `options.pitch` was given, then `rotateend` if `options.bearing` was given, then `moveend`. The pitch and bearing events carry `eventData`.
  - `gesture({ bearing, pitch }): void`. Sets whichever is given and pushes ``` `gesture ${JSON.stringify(arg)}` ``` to `calls`. Then it fires `move`, `pitchend` (if pitch was given) and `rotateend` (if bearing was given), each with `{ originalEvent: { type: "pointermove" } }`, and finally `moveend` with no payload.

`update()` does two things:
- sets `needle.style.transform` to `` `rotateX(${pitch}deg) rotateZ(${-bearing}deg)` ``;
- calls `compass.toggleAttribute("data-idle", Math.abs(bearing) < 0.5 && !terrain)`.

It never reads `PHONE`: `style.css` alone decides what idle means per layout.

  - `rgiMap.setTerrain(on, { move })`, `rotateBy`, `faceNorth`, `level`, `onCamera`, `onTilt` from Task 1;
  - `FakeMap.gesture` from Task 1;
  - `mountTerrain(root, { on, onChange }) → { set(on) }`, which exists today.
- Produces: a page-local constant `TILT_3D = 5` and a function `threeD(on: boolean, move: boolean)` in `js/app.js`. These are the only way the page switches 3D.

Wiring, in this order inside `wire()`:
1. Mount the compass into `#controls` before `mountTerrain`, so the DOM order (compass, 3D, zoom) matches the desktop column and its Tab order. On the phone, `order: 1` moves the compass under 3D.
2. `threeD(on, move)` does the following in order:
   - sets `state.terrain`;
   - calls `terrain.set(on)`, which presses the button and shows or hides the notice;
   - calls `rgiMap.setTerrain(on, { move })`, `save()` and `status?.refresh()`;
   - refreshes the compass with `compass.update({ bearing: map.getBearing(), pitch: map.getPitch(), terrain: state.terrain })`.
3. Callback wiring:
   - The 3D button's `onChange(on)` calls `threeD(on, true)`.
   - `onCamera` refreshes the compass in the same way, and the compass is refreshed once at mount.
   - `onRotate(degrees)` calls `rgiMap.rotateBy(degrees)`.
   - `onReset()` calls `threeD(false, true)` when `state.terrain` is on. Its ease already goes to pitch 0 and bearing 0. Otherwise it calls `rgiMap.faceNorth()`.
4. `onTilt(pitch)`:
   - `pitch >= TILT_3D`: calls `threeD(true, false)` unless 3D is already on.
   - Otherwise: calls `threeD(false, false)` if 3D is on, then `rgiMap.level()` if `pitch > 0`.
