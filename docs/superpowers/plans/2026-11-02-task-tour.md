# Task Tour Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the welcome on the reader's first map or search interaction. Rework the built tour so each step asks for an action and moves on when the reader does it. The tour survives Use this data and the photo viewer. The welcome gets its new heading and concentric corners.

**Architecture:** `js/tour.js` becomes a small state machine over five steps: find, card, data, terrain, done. A cover mode handles the times when Use this data or the viewer is open. The tour stays app-agnostic. `js/app.js` feeds it state through callbacks (`panel()`, `terrainOn()`) and events (`refresh()`, `interacted()`, `cover()`). `js/usedata.js` and `js/viewer.js` gain open/close hooks.

**Tech Stack:** Plain ES modules, jsdom with `node --test`, Playwright's cached headless shell for the browser check.

**Spec:** `docs/superpowers/specs/2026-11-02-task-tour-design.md`, which revises `docs/superpowers/specs/2026-11-02-welcome-tour-design.md`.

### Task 3: The tour as a state machine

**Files:**
- Modify: `js/tour.js`. Rewrite `mountTour` and keep `placeNear` unchanged.
- Modify: `style.css`. Add `.inline-icon` and `.tour.covering`.
- Test: `tests/tour.test.js`. Keep the four `placeNear` tests and the CSS-hiding test. Replace the flow tests.

**Interfaces:**
- Consumes: `placeNear` (unchanged).
- Produces: `mountTour(root, { anchor, panel, terrainOn, onTakeMe, onEnd }) -> { start(), end(), refresh(), interacted(), cover(by, open), readonly running }`.
  - `anchor(name)` takes one of `"search" | "panel" | "useData" | "terrain" | "done"`. It returns an `Element` or `null`.
  - `panel()` returns `null`, `"glacier"` or `"complex"`.
  - `terrainOn()` returns a boolean.
  - `onTakeMe()` returns a promise of a boolean, as built. On `false`, the button is removed.
  - `onEnd({ byTarget })` keeps its signature. `byTarget` is now always false, since no step ends on a click.
  - `refresh()` re-reads `panel()`, `terrainOn()` and `PHONE`. It moves on when a step's condition is met and re-renders.
  - `interacted()` marks step 2 as interacted. It's a no-op on any other step.
  - `cover(by, open)`: `by` is `"useData"` or `"viewer"`. `open = true` enters cover mode. `open = false` for the same `by` leaves it. A close of `useData` while on step 3 goes to step 4 if `panel()` is set, else to step 1. Any other close returns to the step it covered. On entering cover, when `node.showPopover` exists, the popover is `popover="manual"` and is re-shown (hide, then show), so it sits above the modal dialog in the top layer.
- Step rules, each applied on every render:
  - **find:** a `panel()` → card.
  - **card:** no `panel()` → find.
  - **data:** no `panel()` → find.
  - **terrain:** `terrainOn()` → done.
- Skip moves on as follows:
  - from find → terrain
  - from card → data
  - from data → terrain
  - from terrain → done
- Next (card, after an interaction) → data. Done ends the tour. The `interacted` flag resets whenever step 2 is entered from step 1.
- Rings and placement:
  - find rings `search` (sides `["below"]`).
  - card rings `panel` (sides `["right","above","below"]`).
  - data rings `useData` (same sides).
  - terrain rings `terrain` (sides `["left","below"]`).
  - done rings nothing. It is placed against `anchor("done")`, with sides `["below"]` on the desktop and `["above"]` on the phone.
  - cover rings nothing and gets class `covering`. Its placement comes from CSS (fixed, top-centre on desktop; bottom on phone, above the status line).
- Keep, as built: the ResizeObserver on the ringed target, the Escape rule, the `PHONE` re-render, and the `resize`/`transitionend` re-place. Also keep "Opening…" and the removal of "Take me to a glacier".
